## 1. 待解决困惑（按优先级）

### 🔴 P2-7：普通攻击"挥剑动画+跳扑" —— 根因实锤（2026-08-15 三轮修复完成）

**现象**：黑矛兵普通攻击仍是"用长矛执行剑的劈砍"（挥剑动画+跳扑），v1.3 长矛穿刺（跳过 Attack 原版）看似没生效。

**日志没暴露问题的原因（三处）**：
1. **根因被埋**：最新会话日志有一行 `[ERROR] [BS v1.3] Awake 初始化异常: System.TypeLoadException: Could not load type 'System.Func`2' from assembly 'mscorlib, Version=4.0.0.0'`——它是唯一信号，但只有一行，被 67 万行日志淹没；且 mod 其余功能（生成/染色/冲锋/刺击表现）继续运行，让人误以为 Patch 都生效了。
2. **`PatchSwordsman` 整体 JIT 崩溃**：旧代码 `typeof(Func<Agent,bool>)`（net472 编译 → `[mscorlib 4.0.0.0]System.Func`2`）在 JIT 编译 PatchSwordsman 方法体时抛 TypeLoadException，**range/GetAttack/Attack/AttackUpdate 四条 Patch 全部静默失效**。启动日志里因此永远只有 `LevelNode.Setup` 一条成功。
3. **日志信号被误读**：`body=hop` 是 `hopping.active`（容器状态，几乎恒 true）而非跳扑；`anim=hash=81563449` 无人能读懂（不知道是 Idle/Run/Attack）。

**⚠️ 更深一层的病根（第二轮实测 2026-08-15 21:0x）**：游戏本体程序集引用 `mscorlib 4.0.0.0`（Unity 2018.4 .NET 4.x 配置），运行时 mscorlib 也是 4.0.0.0——**但 Unity Mono 的 mscorlib 里 `System.Action`/`System.Func` 是 type-forward（真正实现移到 System.Core）**。因此：
- **游戏自己**（Unity 编译器）引用它们时走 `[System.Core 4.0.0.0]` → 运行时正常；
- **net472 编译的 mod** 引用它们时走 `[mscorlib 4.0.0.0]` → MonoMod 反射枚举 mod 方法签名时抛 `Could not load type 'System.Action' from mscorlib 4.0.0.0`（见 On.Landing.add_Spawn 堆栈）。
- 结论：**mod 内禁止直接引用 `System.Action`/`System.Func`（含一切会隐式生成它们的写法：lambda 转 Action、List.ForEach、链式委托）**。net35 目标框架也不行（游戏引用 mscorlib 4.0，net35 编译直接 MSB3258 拒绝）。正确姿势 = net472 + 自定义委托（如 `delegate void PatchJob()`）代替 Action。
- **⚠️ 第三轮雷区（2026-08-15 21:20 实测，op_Equality）**：第二轮修掉 Action 后，启动日志仍**全部 FAIL**：`MissingMethodException: Method not found: 'System.Reflection.MethodInfo.op_Equality'` / `'System.Reflection.PropertyInfo.op_Inequality'`。根因：TryPatch 的 lambda 对反射对象（`MethodInfo`/`PropertyInfo`）用 `==`/`!=` null——net472 编译产物引用 `System.Reflection.MethodInfo::op_Equality` / `PropertyInfo::op_Inequality`（.NET 4.0 的 mscorlib 才声明这些运算符），**Unity 运行时 mscorlib 没有** → 执行到 lambda 即 MissingMethodException，6 条 Patch 全 FAIL。旧代码与 `SwordRemover.cs` 注释早已立下铁律（"Mono 2.0 没有 FieldInfo.op_Equality，判空必须用 ReferenceEquals"），本轮新代码违反。修复：反射对象判空一律 `ReferenceEquals(x, null)`（含 `AgentPlayAnimationPrefix` 的 `m.DeclaringType != null`、`CaptureScreenshotOnce` 的 `mi != null`）；产物 Mono.Cecil 扫描确认 `System.Reflection.*` 的 op_Equality/op_Inequality **0 处**。

**证据链（日志检索）**：

### ✅ P0-1：冲锋触发不可靠 —— 已解决

**现象**：黑矛兵有时不冲锋，而是普通走路接近我方阵前。
**根因**：独立 6m 扫描与 Swordsman 大脑的战术目标不同步；且协同防重把所有目标锁光后放弃冲锋。
**修复（已实装）**：
- 触发改为**大脑目标优先**：`GetBrainTarget()` 取 `Swordsman.target` / `enemyAgent`，方向朝目标 `navPos`（Twohanded 式）；大脑无目标才退回 6m 扫描兜底。
- 协同防重**软降级**：未锁定目标优先；全部被锁则选"锁定者最少"的目标（不再锁光放弃）。
- 大脑目标也参与防重（`IsLockedByOthers`）：已被其他黑矛兵锁定则换扫描目标，避免挤同一人。
- 目标贴脸（<0.6m）不冲，交给普通攻击。

### ✅ P0-2：冲锋命中率低 —— 已解决

**现象**：矛尖扫过我方单位但没有命中。
**根因**：命中锚点用 `navPos` 算矛尖，而冲锋时 `transform` 滞后 navPos 约 1m（Body 追赶式动画）→ 命中点领先可见矛尖 1m+（"隔空命中"）。
**修复（已实装）**：
- 命中锚点改用**视觉长矛**（`_spearTransform.position`），命中=所见。
- 查询改用 `AgentEnumerators.GetStaticListRadiusSorted`（直接查游戏 Agent 列表，不受物理层/碰撞体干扰）。
- 线宽定为单矛 `HitRadius=0.5m`（原版单兵 ≈0.46m），命中范围与视觉一致。

### 🟢 P2-6：剑的视觉残留 —— ✅ 已验证解决（2026-08-15 二次修复）

**现象**：黑矛兵身体动画帧里带剑，去剑难度大。

**研究突破（2026-08-15，像素级定位 + 运行时诊断）**：
- 剑烘焙在 **`OnehandedXXXX` 动画帧**的**帧右侧 x≈29~38**（暗红垂直带：宽阈值 70/40/20 命中 **201 像素**、窄阈值 90/25/10 命中 132）。之前误以为在 `Swordsman0001`——那是 SwordShield 单位的帧；黑矛兵（Viking_Sword 基底）实际用 **`Onehanded` 帧**。
- 帧纹理是**共享 2048x1024 精灵图集**（`SpriteAtlasTexture-Sprites (Group 0)-2048x1024-fmt4`），必须**克隆**后按帧 rect 擦除（不能改共享资源）。
- `sprite2 = PartTex_Sword`（`PartTex_Median_BlurAlpha` 图集的 (192,0,64,126) 单元）—— 身体外观来源；`SetSprite2` 是游戏设计的换部件机制（安全）。
- 网格状态：`meshColors0=(0,96,2,0)`、`meshUV0=(0.122,0.805)` —— bSprite 交换后顶点色/UV 均正常。

**⚠️ 关键发现：`bSprite` 交换会破坏身体渲染（躯干透明）**
- 即使**只擦剑区域（201 像素）**、顶点色/UV 全部正常，只要把渲染 Sprite 换成新建的克隆 Sprite（`Sprite.Create`），`BatchedSprite` 的批量渲染就坏 → **躯干透明**（与擦除像素量无关）。
- 之前"整图集擦除 71710 像素导致身体透明"的结论需修正：**`bSprite` 交换本身才是破坏渲染的真凶**。

**✅ 修复方案（已游戏内验证：剑刃消失、躯干完好）**：不交换 bSprite，**只替换材质块的 `_MainTex` 为去剑克隆**：
- 网格 UV 本来就指向图集单元；克隆纹理与图集同尺寸 → `_MainTex` 直接采样克隆的同一单元即可渲染"去剑帧"；
- 全程不碰 `bSprite` / `sprite` / 网格 / 顶点色 → 不触发批量渲染重建。
- 实现：`SwordRemover.EnsureErasedTexture`（共享克隆 + 每帧 rect 只擦一次 + 安全阀）+ `LateUpdate` 里 `block.SetTexture("_MainTex", clone)` + `ComittBlock()`。

**🔬 二次发现（2026-08-15）**：游戏内验证后剑刃消失但**剑柄还在** → 离线统计定位：
- **剑柄/护手 = 剑刃 bbox 外侧的非红不透明像素**（灰金属色，不在 70/40/20 阈值内；如 0002 帧剑柄 x37-40）。
- 且**剑到身体左侧的帧（0030~0033、0058~0059，剑刃 x2-22）原 `x≥28` 区域会漏擦**（整剑闪回）。
- **修复 = 方向感知擦除**：① 整帧红暗像素（左右侧都擦）；② 剑外侧非红（右偏剑擦 `x≥剑右缘-2`、左偏剑擦 `x≤剑左缘+2`，bbox 上下 ±6px 带）；③ 居中剑不擦外侧。离线 59 帧全量模拟：残留=0、身体误擦=0、占比最高 15.7%（<20% 安全阀）。

**⚔️ 顺带修复："攻击逻辑仍是剑"**：`Swordsman.range` 补丁原返回 `radius×0.7×1.3≈0.118m`（贴脸）→ 改为 `radius×0.7+0.6≈0.69m`（矛长+身体半程），攻击在矛尖够到的地方触发。

**诊断工具（已内置）**：
- `去剑·运行时诊断`：帧像素 ASCII 图（`S`=窄阈值红暗 90/25/10、`s`=宽阈值红暗 70/40/20、`#`=亮色、`.`=不透明）+ **sprite2 单元 ASCII 图**（全局一次）+ 网格状态。
- `[去剑诊断]`：不透明数 / 宽窄阈值命中数 / 红暗 bbox。
- `ReadMeshState`：`meshColors0/meshUV0`（检测交换后渲染状态）。

**🔬 三次发现（2026-08-15，本轮）——剑柄残留 / 近战剑闪回 / 挥砍长矛**：
- **剑柄残留根因**：动画帧颜色实为 **UV 编码**（R/G 通道 = 采样 `PartTex_Sword` 的 UV，`_UV = color.SetB(0)-Color.white`），剑柄=剑刃基部靠身体一侧的**非红**像素（如 0030 帧剑柄 145px、0025 帧 47px），与"持剑的手/臂"重叠——旧算法外侧带擦的是**尖端侧**（背景），剑柄从未被擦到；左偏剑帧（0031~0033）剑柄在**基部右侧**也被漏。
- **近战剑闪回根因**：`EnsureErasedTexture` 逐帧"首次显示后才擦"→ 每个新帧渲染时**晚一帧**，慢放可见剑闪回。
- **修复（已实现）**：① **预擦除全部 Onehanded 帧**（`PreEraseAllOnehanded`：`Resources.FindObjectsOfTypeAll<Sprite>` 枚举同图集所有 Onehanded 帧一次性擦除，共享像素数组只上传一次 → 动画播放零闪回）；② **剑柄带改到基部身体侧**（右偏剑擦 `x∈[rx0-HiltBandPx, rx0+2]`、左偏剑擦 `x∈[rx1-2, rx1+HiltBandPx]`，bbox 上下 ±6px）；③ **安全阀只看红暗命中**（`CountRed`，剑柄带几何有界不计入，避免整帧被跳过）。
- **离线模拟（新逻辑，59 帧）**：剑柄带残留=0、身体超带误擦=0；剑柄带会连带擦掉"持剑手/臂"紧贴剑刃基部的少量像素（≤8px 宽窄条，可接受，可在游戏内复核观感）。
- **新增调参**：`HiltBandPx`（当前 5）、`ThrustDistance/Rise/Fall`（见刺击）。

**⚔️ 近战刺击（视觉"刺"而非"挥砍长矛"）**：
- 基底 Swordsman 攻击动画是挥剑帧（无法换），但剑已擦除、矛是唯一武器视觉；新增 `SpearChargeComponent.UpdateMeleeThrust()`：**`Swordsman.attack.active` 时长矛对准目标并沿矛身前向快速突刺 `ThrustDistance=0.45m`**（0.06s 刺出 / 0.28s 收回），观感为"刺"而非"挥砍长矛"。与冲锋共用 `_spearTargetRot` 插值，互不冲突。

**🔻 四次发现（2026-08-15，实测回退）——剑柄带会挖掉身体**：
- 实测日志：`擦除=439`（比纯剑刃 201 多出 238）→ 剑柄带把持剑手臂/躯干成片擦成透明 → **"身躯一半消失"**。**结论：帧内剑柄与身体（持剑的手）在像素级重叠，帧级擦除永远无法两全**。
- **已回退**：`HiltBandPx=-1`（剑柄带禁用，三处守卫 `HiltBandPx>0`）→ 身体恢复、只保留安全红暗剑刃擦除。
- **剑柄残留的正解 = 部件贴图（sprite2）方案**：最终渲染 = 帧 RG(UV) 采样 `PartTex_Sword`。`SetSprite2` 把部件 rect 原点编码进顶点色（`G=96 = rect.x/2=192/2`）。下一步应从 `_PartTex` 克隆里抹掉剑区（亮银像素），而非改帧。离线 UV 解码 4 组合均无法稳定区分剑/身体，需运行时探针或读取真实 shader。
