## 1. 问题一：玩家方技能/数值如何在敌方上复现

### 1.1 原版技能复现的"官方通道"（数据库源码验证）

敌方（维京）没有玩家方的 Upgrade Ability，但复用同一套 Agent 框架，技能注入有三条通道：

```
通道①  IBrainAction        —— 战斗技能（Pike Charge / 掷斧 / 刺击）
        Brain.Setup(): actions = GetComponentsInChildren<IBrainAction>(true)   (Brain.cs:87)
        Brain.MaybeAct(): 遍历 actions，第一个返回 true 的获胜                (Brain.cs:39-49)
        ★ 只在 Swordsman.IdleUpdate() 的 hz8 节拍里被调用                     (Swordsman.cs:243-248)

通道②  IAttackResponder    —— 受击/伤害修正（盾格挡、护甲、冲刺免疫）
        Agent.Setup(): attackResponders = GetComponentsInChildren<IAttackResponder>(true).ToList()
                                                                               (Agent.cs:401)
        Agent.DealDamage(): 遍历 attackResponders → ModifyAttack(ref attack)    (Agent.cs:563-575)

通道③  AgentState + exclusives —— 技能状态机（互斥锁大脑）
        exclusives = new AgentState("Exclusives", aliveAndGrounded, false, false) (Agent.cs:409)
        原版 PikeCharge 在 exclusives 下建 pikeCharge→anticipation→charge→travelling/arrived
```

**关键时序约束（v1.3 已经踩对一半）**：
- `Agent.Setup()` / `Brain.Setup()` 在 `Squad.CreateAgent()` 里执行，**早于** `Landing.Spawn` 的 postfix。
- 所以后挂的 `SpearChargeComponent/SpearStabAction` **必须手动** `brain.actions.Add(...)` —— v1.3 的 `RegisterBrainAction()` 做对了 ✅。
- 但**后加的 `IAttackResponder`（如护甲组件）也必须手动 `agent.attackResponders.Add(...)`**，否则不生效 —— v1.3 没做。

### 1.2 Pike Charge 逐行对照（原版 vs v1.3）—— 位移橡皮筋的真正根因

| 原版（PikeChargeComponent.cs / PikeChargeAbility.cs） | v1.3（SpearChargeComponent.cs） | 判定 |
|---|---|---|
| `travelling.OnUpdate: agent.movability = 0.2f; agent.enemyMovability = 0.1f` | `maxSpeed=0; movability=0` | ❌ 根因：`FixedUpdateAgent` 末尾 `speed = maxSpeed`（Agent.cs:941），maxSpeed=0 → Body 的 standing/stepping 踏步动画追不上 navPos → "橡皮筋"。原版从不把 maxSpeed 设 0。 |
| `charge.OnUpdate: NavPos c = ability.current; c.pos += positionInFormation; agent.navPos = c; agent.LookInDirection(dir,720,20)` | `agent.navPos = np`（每帧 LateUpdate） | ✅ 方向正确（整体赋值 NavPos） |
| 位移推进点：`Lerp(start.pos, end.pos, t/duration)`（固定起点插值） | `newPos = transform.position + dir*speed*dt`（以被橡皮筋拖慢的 transform 为基准） | ⚠️ 应改为 `_chargeStartPos + _chargeDirection * ChargeSpeed * t` |
| 命中：`AgentEnumerators.GetStaticListRadius(vector + dir*spearLength/2, radius=0.732, faction.enemy)` | `Physics.OverlapSphere(pos, 0.4f)` | ❌ 半径 0.4 太小；Physics 会命中非 Agent 碰撞体 |
| 伤害：`spear.attackSetting + ability.settings.attackSettings`，`damage *= energy` | 固定 `StabDamage=3` | ⚠️ 应接 `Swordsman.damage`（等级化） |
| 触发：`agent.aliveAndGrounded.active` | `aliveAndGrounded + navPos.onMain` | ✅（onMain 拦截敌舰触发，NavPos.cs:213-219） |

**修正后的 DoCharging 骨架**：

```csharp
// 状态切换（StartCharging）时：
_agent.movability = 0.2f;          // 原版值，别设 0
_agent.enemyMovability = 0.1f;     // 原版值
_chargeStartPos = _agent.navPos.wPos;
_chargeStartT = Time.time;
_agent.body.hopping.SetActive(false);   // 关掉"踏步追赶"动画层
_agent.body.sliding.SetActive(true);    // 开启"直接贴 navPos"的滑动层 → transform 即时跟随

// DoCharging/LateUpdate 里：
float t = (Time.time - _chargeStartT) / ChargingMaxTime;   // 0→1
Vector3 target = _chargeStartPos + _chargeDirection * ChargeSpeed * t;  // 固定起点插值（同原版 Lerp）
NavPos np = _agent.navPos;
if (np.valid)
{
    Vector3 local = np.transform.InverseTransformPoint(target);
    if (!np.MoveTo(local))
        np = new NavPos(np.navigationMesh, target, true, 1f);   // 原版同款回退
    _agent.navPos = np;
}
```

> 说明：`Body.sliding.OnUpdate` 直接 `transform.position = navPos.wPos`（Body.cs:47），能彻底消除"navPos 推进了、transform 没跟上"的橡皮筋。

## 2. 问题二：美术素材复用后的逻辑残留（为什么销毁不掉）

### 2.1 残留清单（来自 v1.3 日志组件树 + 源码）

`Viking_SwordShield(Clone)` 预制体自带组件：

| 组件 | 接口 | 残留行为 | 保留/清除 |
|---|---|---|---|
| `Shield` | IAttackResponder | 格挡近战/箭矢（`ModifyAttack` 直接调用，`enabled=false` **无效**） | ❌ 清除 |
| `Arsonist` | IBrainAction + IAgentOrder | 靠近房屋时**扔火把烧房**（`MaybeAct` 里 `pather.house` 判定） | ❌ 清除 |
| `Pirate` | IBrainAction + IAgentOrder | 敌舰登岛/下船逻辑（`RemoveFromShip` 会自己从 actions 移除） | ✅ 必须保留 |
| `KillAllEnemies` | IAgentOrder | 向敌方单位逼近 | ✅ 保留 |
| `Swordsman` | Brain(CloseCombatBrain) | 近战大脑 | ✅ 保留 |
| `ShieldAimer` 子对象 | — | 盾牌瞄准动画 | ❌ 禁用 |

### 2.2 "销毁不掉"的三个机制原因

1. **`enabled=false` 无效**：`ModifyAttack`/`MaybeAct`/`WantsControl` 是**直接 C# 调用**，不经过 Unity 消息循环。`Shield.enabled=false` 后 `Agent.DealDamage` 依然会调它的 `ModifyAttack` → 盾牌照样格挡。
2. **缓存列表残留**：`agent.attackResponders`(List, public)、`brain.actions`(List, public)、`brain.orderList`(List, **private**) 都在 Setup 时缓存。只 `Destroy(component)` 不移出列表 → 列表里是"Unity 假 null"，`Brain.MaybeAct()` 调 `actions[i].MaybeAct()` 直接抛 `MissingReferenceException`。
3. **视觉层残留**：身体上画的"剑+盾"来自 `SpriteAnimator.sprite2` 部件纹理（`PartTex_SwordShield.png`），**不在**"按名字禁用的子对象"里。`AgentTextureBaker` 会把所有 active 子对象烘焙进共享纹理。

### 2.3 解决方案（按优先级）

#### 层次 A：预制体层面剥离（根治，推荐）⭐

思路：`RegisterBlackSpearman` 时**不直接借 `src.viking`**，而是先 `Instantiate` 一份"已剥离"的模板，设进新 VR 的 `viking` 字段。之后 `VikingReference.Start()` 实例化的、`Squad.CreateAgent` 用的都是**干净预制体** → `Agent.Setup()`/`Brain.Setup()` 收集时根本没有 Shield/Arsonist，**从根源上无残留**。

时序保证：注册发生在 `GameSetup.Awake` postfix；新 VR 的 `Start()` 下一帧才跑；**有窗口**。

```csharp
// Plugin.RegisterBlackSpearman 内，替换"直接借用 src.viking"：
GameObject stripped = UnityEngine.Object.Instantiate(src.viking.gameObject);
stripped.name = "BlackSpearman_StrippedTemplate";
stripped.SetActive(false);                        // 只做模板，不进场景

// ① 摧毁逻辑残留（Destroy 而不是 enabled=false）
var shield = stripped.GetComponent<Shield>();
if (shield != null) UnityEngine.Object.Destroy(shield);
var arsonist = stripped.GetComponent<Arsonist>();
if (arsonist != null) UnityEngine.Object.Destroy(arsonist);

// ② 禁用盾/剑视觉子对象（按名称）
string[] keys = { "shield", "sword", "weapon", "aimer", "盾", "剑" };
foreach (Transform t in stripped.GetComponentsInChildren<Transform>(true))
{
    if (t == null || t.gameObject == stripped) continue;
    string n = t.name.ToLowerInvariant();
    for (int i = 0; i < keys.Length; i++)
        if (n.Contains(keys[i].ToLowerInvariant())) { t.gameObject.SetActive(false); break; }
}

// ③ 换部件纹理：去掉身体上的盾（从 Viking_Sword 借一个"纯剑" sprite2）
Sprite swordPartTex = GetSwordOnlySprite2();      // 见下
if (swordPartTex != null)
{
    var sa = stripped.GetComponentInChildren<SpriteAnimator>(true);
    if (sa != null) sa.sprite2 = swordPartTex;
}

// ④ 反射设 viking 字段（注意 .NET3.5：用 ReferenceEquals 判空）
_vikingField.SetValue(newVR, stripped.GetComponent<VikingAgent>());
```

> `GetSwordOnlySprite2()`：从 `LevelStateObjectReferences.dict["Viking_Sword"]` 的 `vikingClone`（或运行时 Sword 敌人）上取 `GetComponentInChildren<SpriteAnimator>(true).sprite2`。`SpriteAnimator.SetSprite2` 会把部件纹理写入 `_PartTex` 并编码到 color 的 R/G 通道（SpriteAnimator.cs:107-117）——**换完不要乱改 R/G**。

#### 层次 B：实例级剥离（兜底，适合不想动注册流程的情况）

放在 `ApplyToAgent` 里，**顺序必须先移出缓存再 Destroy**：

```csharp
// ① Shield：先移出 attackResponders 缓存，再销毁
var shield = a.GetComponent<Shield>();
if (shield != null)
{
    if (a.attackResponders != null) a.attackResponders.Remove(shield);
    UnityEngine.Object.Destroy(shield);
}
a.shield = false;

// ② Arsonist：移出 brain.actions + (反射) brain.orderList，再销毁
var arsonist = a.GetComponent<Arsonist>();
if (arsonist != null)
{
    if (a.brain != null && a.brain.actions != null) a.brain.actions.Remove(arsonist);
    RemoveFromOrderList(a.brain, arsonist);   // orderList 是 private → 反射移除
    UnityEngine.Object.Destroy(arsonist);
    if (a.brain != null) a.brain.PickNewOrder();
}

// ③ 后加的 IAttackResponder 需要手动入列（如果要加护甲/免伤）
// if (armor != null) a.attackResponders.Add(armor);
```

```csharp
static void RemoveFromOrderList(Brain brain, object item)
{
    if (brain == null) return;
    try
    {
        var f = typeof(Brain).GetField("orderList",
            System.Reflection.BindingFlags.Instance | System.Reflection.BindingFlags.NonPublic);
        if (f == null) return;
        var list = f.GetValue(brain) as System.Collections.IList;
        if (list == null) return;
        for (int i = 0; i < list.Count; i++)
            if (ReferenceEquals(list[i], item)) { list.RemoveAt(i); break; }
    }
    catch { }
}
```

#### 层次 C：视觉换肤（去盾去剑的"画面残留"）

- 身体上的盾/剑 = `sprite2` 部件纹理 → 换 `PartTex_Sword`（见层次 A ③）。
- 染色只动 B 通道 ✅（v1.3 `BlackSpearmanVisual` 已正确；R/G 是部件纹理网格编码）。
- 长矛克隆后要把克隆里的 `BatchedSprite`/`SpriteAnimator` 的 `color` 一并染黑（`BlackSpearmanVisual.Recolor` 已遍历所有 `BatchedSprite` ✅）。
- 日志 `spearSprite=False`：`FindSpearTemplate` 找到的是运行时 agent 的 `spearAim`，其 `Spear.spearSprite` 字段为 null。**优先找 PrefabManager 里的原始预制件**（`ScriptableObjectSingleton<PrefabManager>.instance`）或缓存 `spearAnim` 子节点的 `BatchedSprite`，不要依赖运行时 agent 的序列化引用。

## 6. 落地结果（2026-08-14 定稿）

**技能效果实现成功** —— 黑矛兵成为"登岛长矛突击"型战术单位：

- **触发**：登岛后优先跟随 Swordsman 大脑目标（Twohanded 式），方向朝目标 `navPos`；大脑无目标才退回 6m 扫描；协同防重软降级。
- **表现**：0.5s 举矛前摇 → 非追踪直线冲锋（5m/s，穿透锁定格 1.5m）→ 沿途单矛线宽 0.5m 扫过一排（能量 ×0.8 递减）→ 终点爆发（伤害 ×0.3、击退 +2、撞飞）→ 后退 0.6m → ⚠️ 4.25s 冷却（08-14 快照值，**07-15 用户指令延长为 10s 定稿**，见 §7.9）。
- **可躲高收益**：非追踪 + 前摇可见 + 线宽 0.5m → 横向拉开即躲过，躲过则黑矛兵空大陷入长后摇。
- **战术价值**：逼迫我方放弃窄道/少接战面地形、转入开阔地拉扯，或阻碍单位转场——与不同兵种同场可碰撞出火花。

## 7. 去剑研究（2026-08-15，快照）—— 精灵渲染管线与 bSprite 交换陷阱

> 📎 本章与[开发日志.md](开发日志.md)的「P2-6 剑的视觉残留 / 五次进展」为同一知识的两份表述（技术沉淀 vs 逐轮流水），
> 去剑最终形态（帧擦除 + 部件贴图分区压暗 + 安全阀）以代码与开发日志为准，本章保留渲染管线精读与 bSprite 陷阱的结论。
> 目标：移除黑矛兵身体动画帧里烘焙的剑。攻击逻辑早已是长矛（GetAttack patch），剑只是视觉残留。

### 7.1 渲染管线精读（源码 + 运行时诊断）

```
sprite  （_MainTex） = OnehandedXXXX 动画帧（身体姿势 + 剑），位于共享 2048x1024 精灵图集
sprite2 （_PartTex） = PartTex_Sword（PartTex_Median_BlurAlpha 图集 (192,0,64,126) 单元）→ 身体外观来源
渲染：BatchedSprite 禁用 SpriteRenderer，用 MeshRenderer 子对象 + mesh + MaterialPropertyBlock(_MainTex/_PartTex)
顶点色 R/G = sprite2 图集编码，B = 染黑通道（recolor 设 0.01）
```

- 剑精确位置：`Onehanded0002` 帧 rect=(250.08,824.05,42.90,70.88)，剑在帧内局部 **x≈29~38**（红暗 bbox=(279,858)-(288,881)）。
- 颜色签名：宽阈值 `R>70,G<40,B<20` 命中 **201** 像素（剑刃+剑柄）；窄阈值 90/25/10 命中 132（只剑刃）。
- 各帧均如此（0002/0003/0011/0012/0013/0014/0004/0007：205~226 像素）。

### 7.2 关键陷阱：`bSprite` 交换会破坏身体渲染（躯干透明）

- 实验序列：
  1. 整图集擦除（region=null）→ 误擦 71710 像素 → 身体透明（早期误判为"擦多了"）。
  2. 按帧 rect + 窄阈值 → 擦 132 → 身体仍透明。
  3. 按帧 rect + 宽阈值 + 区域限制 x≥28 → **擦 201（剑全擦）、身体像素完好、网格状态正常**（`meshColors0=(0,96,2,0)`、`meshUV0=(0.122,0.805)`）→ **躯干仍透明**。
- **结论：身体透明与像素擦除无关，是 `bSprite` 交换（把渲染 Sprite 换成 `Sprite.Create` 新建对象）本身破坏 BatchedSprite 批量渲染。**

### 7.3 修复方案（✅ 已游戏内验证：剑刃消失、躯干完好）

**不交换 bSprite，只替换材质块 `_MainTex` 为去剑克隆**：
- 网格 UV 指向图集单元；克隆纹理与图集同尺寸（2048x1024）→ `_MainTex` 采样克隆同一单元即渲染"去剑帧"。
- 不碰 `bSprite`/`sprite`/网格/顶点色 → 不触发批量渲染重建。
- 实现：`SwordRemover.EnsureErasedTexture`（共享克隆 + 每帧 rect 擦一次 + 安全阀）+ `block.SetTexture("_MainTex", clone)` + `ComittBlock()`。

### 7.4 诊断工具（`SwordRemover` 内置）

- `去剑·运行时诊断`：帧像素 ASCII 图（`S`=窄阈值 90/25/10、`s`=宽阈值 70/40/20、`#`=亮色、`.`=不透明）+ sprite2 单元 ASCII 图 + 网格状态。
- `[去剑诊断]`：不透明数 / 宽窄阈值命中数 / 红暗 bbox（图集坐标）。
- `ReadMeshState`：`meshColors0/meshUV0` —— 检测交换后渲染状态是否完好。

### 7.5 二次发现与修复（2026-08-15，剑柄残留 + 左侧帧漏擦 + 攻击距离仍是剑）

**① 剑柄为何还在 —— 剑柄是非红像素（帧内），不在 70/40/20 阈值里**
- 离线统计（`analyze_sword.py`）：剑柄/护手 = 剑刃 bbox **外侧紧贴的非红不透明像素**（灰金属色），每帧 26~175 个；
  例如 `Onehanded0002`：剑刃红暗 x29-38，剑柄在 x37-40（与刃缘重叠 ≤2px + 外侧）。
- 原擦除只认红暗 → 剑柄（非红）漏网；且**剑到身体左侧的帧（0030~0033、0058~0059，剑刃 x2-22）`x≥28` 固定区域完全漏擦**（整把剑闪回）。

**② 方向感知擦除（`GetSwordBounds` + `CountMatch` + `EraseSwordInFrame`）**
- ① 整帧 rect 内红暗像素 → 剑刃（身体左/右侧都擦）；
- ② 剑刃外侧非红不透明像素：右偏剑擦 `x ≥ 剑右缘-2`、左偏剑擦 `x ≤ 剑左缘+2`，仅 bbox 上下 ±6px 纵向带 → 剑柄/护手；
- ③ 居中剑（|剑心-帧心| < 5px）不擦外侧 → 避免误擦居中持剑身体；
- 安全阀 20% 不变。**离线全量验证（`validate_erase.py`，59 帧）**：剑区残留=0、内侧误擦=0、擦除占比最高 15.7%（<20%，无帧被跳过）。

**③ 攻击逻辑"仍是剑"的根源 —— `Swordsman.range` 补丁只给了 0.118m**
- `GetAttack` patch 早已是长矛（伤害/击退/眩晕/音效），但 `SwordsmanRangePostfix` 返回 `radius×0.7×1.3 ≈ 0.118m`——**贴脸距离**，黑矛兵必须站到剑的距离才出手 → 手感就是剑。
- 修复：`range = radius×0.7 + 0.6`（矛长 0.6m + 身体半程 ≈ 0.69m），攻击在矛尖够得到的位置触发 → 长矛刺击手感。
- 遗留：攻击动画仍是挥剑帧（Onehanded，无法换），但剑已擦除 + 矛朝向盖过挥剑，观感为"矛刺"。

### 7.9 刺击"抽动"修复 + 冷却 10s + 盾牌格挡（2026-08-15，七次进展，✅ 定稿）

**刺击抽动根因（对照 Agent.cs 源码确认）**：
1. `Agent.SetDirection(dir)` 是**瞬时** `transform.rotation = LookRotation(dir)`（Agent.cs:760-768）——不是渐进转向。旧 `SwordsmanAttackUpdatePrefix` 攻击期间每帧 `SetDirection(活动目标当前位置)`，身体朝向随目标位移/自旋逐帧阶跃；
2. 旧 `UpdateMeleeThrust` 每帧 `InverseTransformDirection(_thrustDirWorld)` 重算本地偏移 → 与 ① 叠加，本地偏移逐帧跳变 = 肉眼可见的"小的抽动"；
3. 旧 `TryGetAimRotation` 的 `LookRotation(dir, agent.right)` 在目标位于角色侧向（dir ∥ agent.right）时退化 → roll 翻转 180°（矛精灵上下颠倒；日志 `spearWorldRot=(0,179.5,180)`）。

**修复（攻击开始瞬间两处同帧锁死 + 全程零重算）**：
```csharp
// ① 身体先 snap 对准突刺方向，再锁定本地位移（只算一次）
try { _agent.SetDirection(_thrustDirWorld); } catch { }
_thrustOffsetLocal = _agent.transform.InverseTransformDirection(_thrustDirWorld) * ThrustDistance;
// ② 稳定朝向：虚拟 right = cross(worldUp, dir) 恒 ⊥ dir，永不翻转（正对目标时 ≡ 旧式；
//     ⚠️ 首版误写 cross(dir, up) = −agent.right，roll 恒差 180°，验证日志 (0,X,180) vs 冲锋 (0,X,0) 暴露后修正）
Vector3 stableRight = Vector3.Cross(Vector3.up, _thrustDirWorld);
_spearTargetRot = Quaternion.LookRotation(_thrustDirWorld, stableRight.normalized) * Quaternion.Euler(0f, 0f, 90f);
// ③ 攻击中只放大位移：localPosition = _spearBaseLocalPos + _thrustOffsetLocal * _thrust
```
- `Plugin.SwordsmanAttackUpdatePrefix` 攻击期间面向改用 `SpearChargeComponent.LockedThrustDirection`（固定值），不再追活动目标。
- `SpearChargeComponent` 新增公开属性 `IsThrustDirectionLocked` / `LockedThrustDirection` 供 Plugin 读取。

**冲锋冷却**：`CooldownTime` 4.25s → **10s**（`SpearChargeComponent.cs:22`）。表现本身（触发/位移/命中/爆发/后退）全部未动 —— 定稿技能不被改变。

**盾牌格挡**（`BlackSpearmanShield.cs`，复刻 `Shield.ModifyAttack`，Shield.cs:166）：
- 近战（`CloseCombatBrain`）正面 → 伤害归零 + 盾击音效；
- 箭矢（`Arrow`）正面 → ×0.05 + 随机 `Smash`/`Bounce`；
- 飞斧（`ThrowingAxe`）正面 → 归零 + `Bounce`；
- 我方长矛（`Spear`）正面 → ×0.2；
- 判定 = `Dot(shield.forward, -attack.direction) > 0.5`；`EnableShield` cfg=false 时仅视觉（ModifyAttack 直接放行）。

**近战命中最终形态（对齐我方 Spear.cs:330/363）**：`DoSpearHit`（主×1 / 副×0.33 贯穿）→ `TestHit`（矛本地空间球）→ `DealSpearDamage`（`Swordsman.damage` 等级化 + `PrefabManager.hitEffect`）。替代 7.7 的 `Swordsman.FirstHit()`（原版事件触发，穿刺不播动画故手动触发）。

**待验证（下一轮实测）**：① 刺击是否完全稳定；② 盾牌 `facing<=0.5f` 与视觉朝向一致性；③ 冲锋 10s 冷却节奏。

**✅ 实测验证（2026-08-15 日志复核）**：刺击本地偏移锁死（`spearLocalPos=(0.000,0.168,z)` 全段无跳变）、y 翻转（矛反指）消除；但暴露 **roll 符号错误**——突刺 `spearWorldRot=(0,X,180)` 与冲锋举矛 `(0,X,0)` 不一致（首版 `Cross(dir,up)` = −agent.right），已修正为 `Cross(up,dir)`（正对目标时 ≡ 旧式）。盾牌近战格挡日志 `facing=0.85/0.97` 生效；`挡箭/挡飞斧/格挡长矛` 待有对应兵种的波次复测。冲锋冷却 10s 由 `EndCharge → _phaseTimer=10f` 确定性保证。

## 10. 渲染管线（去剑/改色/重影的核心战场）

- **身体渲染器**：`SpriteAnimator` 下 **4 个 MeshRenderer（2 主身 + 2 `_MIRROR_ON` 镜像）**，着色器 `ColoredCharacter` 是 **`Cull Off`** → 4 层始终同绘；
  - 两个主身本质不同：**静态主身**（UV 恒 0.152=Swordsman0001 帧图集位置，不随动画更新）vs **动画主身**（UV 随 SpriteAnimator 逐帧更新 = 律动/动画源）；
  - 改黑+头盔提亮后 4 层叠加高对比显形 = 头部抽搐/重影；`SingleBodyMode=2` 只保留动画主身 → 无重影且律动完整。
- **`bSprite` 交换会破坏身体渲染（躯干透明）**：即使只擦剑区、顶点色/UV 全正常，换 Sprite 对象就坏。去剑必须**只替换材质块 `_MainTex`**（网格 UV 指向图集单元，克隆纹理与图集同尺寸直接采样同一单元）。
- **着色器 LERP**：b=0.02 时屏幕色≈克隆色 → 离线压暗克隆即可判定游戏内屏幕表现（无需屏幕采样）。
- **帧纹理**：共享 2048x1024 精灵图集（`SpriteAtlasTexture-Sprites (Group 0)`，ETC2 `fmt4`）→ 必须克隆后按帧 rect 擦除，不能改共享资源。
- **sprite2 部件贴图**：`PartTex_SwordShield`（剑+盾 2D 部件）单元 64x126；身体帧顶点色 R/G 编码 UV，着色器据此采样部件贴图 = 身体外观来源。

## 11. UV 解码与 sprite2 编码

- 帧像素顶点色 `(r,g)` 即部件贴图采样 UV：`u = r/255, v = g/255`（另有 (g,r)、(r,1-g)、(1-r,1-g) 三种候选解码，探针逐一验证）；
- 白框像素 = 帧像素解码 UV 后采样到**亮银部件像素**（>150）→ 渲染成白框；红暗阈值抓不到（G 高），必须按 UV 采样判定；
- `SetSprite2(sprite)` 是游戏设计的换部件机制（安全）；但换完后**烘焙重设 sprite2 会退回原部件** → 帧擦除掩码必须永远按**原版部件**（`_partCacheSprite`）构建。


## 12. NavPos 与位移推进

- **`NavPos` 是结构体**（struct）：`_agent.navPos.pos = newPos` 写在临时副本上 = 静默无效；必须**整体赋值** `agent.navPos = newNavPos`；
- `Agent.FixedUpdateAgent` 里 `wPos = navPos.wPos`，Body 的 standing/stepping/sliding 再据此驱动 `transform.position` → LateUpdate 直接写 `transform.position` 下一帧就被覆盖；
- **权威可走性判定**：`NavPos.MoveTo(local)` 返回 `bestDist == 0f`（IL 反编译确认）——目标点真正落在可走三角形内才为 true；落水面/悬崖返回 false → 冲锋可走性检查用副本调用不污染真实 navPos；
- `MoveTo` 失败回退：`new NavPos(navMesh, worldPos, true, 1f)`（原版同款，贴最近三角形）。

## 13. .NET 运行时兼容坑汇总（Unity 2018 老 Mono / CLR 2.0）

| 坑 | 表现 | 对策 |
|----|------|------|
| `FieldInfo/MethodInfo/PropertyInfo` 的 `==`/`!=` | Mono 2.0 抛 `MissingMethodException: FieldInfo.op_Equality` | 一律 `ReferenceEquals(x, null)` |
| 直接引用 `System.Action`/`System.Func`（含隐式 lambda 转换） | `TypeLoadException: Could not load type 'System.Func\`2' from mscorlib 4.0.0.0`——Unity Mono 的 mscorlib 里它们是 type-forward，真正实现在 System.Core；net472 编译走 mscorlib 引用 → MonoMod 反射枚举签名时崩溃 | mod 内禁止直接引用，改用 `AccessTools` 或手写委托 |
| `lock` 语句 | 编译成 `Monitor.Enter(obj, ref bool)`（4.x 重载） | 避免使用 |
| `string.Join(string, IEnumerable<string>)` | 旧重载缺失 | 用 `BSLog.Join`（StringBuilder 手写） |
| 三参数 `Path.Combine(a,b,c)` | 缺失 | 嵌套两参调用 |
