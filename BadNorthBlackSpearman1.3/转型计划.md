## 三、两处架构修正（影响代码，已对照原版核实）

### ⚠️ 修正 1：一个 shipGroup = 一个 Squad（不是"一艘船"）

敌方生成链（原版 `Landing.cs:195-234`，已核实）：

```
Landing.Spawn()
  → Squad squad = this.shipGroup.squad        (Landing.cs:201)   ← 组级共享小队
  → 每个 ShipLoad 的每个 agent：
      squad.CreateAgent(shipLoad.vikingRef.agent, navPos)   (:219)
      agent.GetOrAddComponent<Pirate>().AddToLongship(ship) (:220)
      agent.GetOrAddComponent<VikingAgent>().vikingReference = shipLoad.vikingRef (:221)
```

- `ShipGroup.squad` 是懒加载的（`ShipGroup.cs:53-63`：`if (!this._squad) this._squad = vikingSquad.SpawnGetFromPrefab(...)`），**同一波（shipGroup）的所有船共享同一个 Squad**。
- 推论：
  - **"共生死"天然成立**（同组共 squad），不用做任何事；
  - **阵型锚点不能挂 Squad**（跨船会串）→ 挂 **Longship / 该船登陆点** 层面——正好是现有 `OnLandingSpawn` 逐船 hook 的位置，`ship.agents` 就是该船的人，直接用；
  - 混编事件/角色记录要按 `agent.vikingReference == 混编引用` 过滤（多船共享同一 squad，事件跨船触发）。

### ⚠️ 修正 2：SquadCoordinator 是玩家侧类，敌方没有实例

已核实 `SquadCoordinator.cs`：抽象 MonoBehaviour，`Setup(Squad)` 里订阅 `squad.onAgentCreated / onAgentRemoved`（`OnAgentCreated/OnAgentRemoved` 虚方法）。子类如 SwordSquadCoordinator 是玩家侧追踪器；**敌方 Viking 侧没有任何 Coordinator 实例**，不能"继承挂到敌方"。

做法：**借鉴它的事件订阅模式**，自建混编管理组件（挂到 shipGroup.squad 或自己的管理对象上），订阅 `squad.onAgentCreated` 记录角色；注意多船共享同一 squad → 用 `agent.vikingReference == 混编引用` 过滤。

## 七、写代码前先背的坑

1. **.NET 3.5 雷区**：禁 `System.Action/Func`（TypeLoadException 会让整批 Patch 静默失效，v1.3 最贵教训）、`string.Join(IEnumerable)`、`FieldInfo == null` 判断——新代码全守。
2. **时序**：`agent.Setup(navPos)` 在 `onAgentCreated` 之前 → `AddComponent` 挂的组件不会被 `Brain.Setup` 收集 → **角色组件要在模板 prefab 上就挂好**（维京长矛 BuildTemplate 就是这么干的），或手动 `RegisterBrainAction`。
3. **弓手大脑是 Archer 不是 Swordsman**——矛兵刺击 Patch 的是 Swordsman 方法，**弓模板别带 Swordsman 组件**。
4. **混编判定用 `prefab == vikingRef.agent`**（vikingClone.agent 属性），不是按名字。
5. **squad 事件跨船串**：`squad.onAgentCreated` 用 `agent.vikingReference` 过滤。
6. **Pirate 冲建筑要压制**（计划风险 1）。
7. **平衡**：混编总战力 > 单兵种，bounty/倍率必须调（计划风险 4）。

## 八、风险与取舍

1. **"排起队列等敌"是全新行为**：原版敌人没有防御阵型概念，防御状态机需自建；且原版 `Pirate` 组件驱动敌人冲建筑，必须压制——这是最大不确定性。
2. **Squad.prefab 单兵种假设**：Squad 的命名/补充/UI 路径假设单 prefab；混编需容忍（敌人侧影响可控，不涉及玩家补给）。
3. **弓手前排化**：原版弓手会贴脸射击，需加"远离前排"约束，否则阵型失效。
4. **混编的平衡**：三兵种同队 = 总战力提升，需调 bounty/配额/血量倍率，避免碾压。
5. **冲锋与阵型的冲突**：长矛冲锋会脱离阵线（穿透+回退 0.6m），回退落点必须精确回到中列，否则打乱阵型——冲锋触发/落点要跟格位联动。
